### Concrete integration gaps found in the current source

1. `websocket/manager.rs::Assignments` stores one worker per market. Both subscription branches in `worker.rs` publish `source_slot: 0`; `store.rs` also hardcodes slot 0 for `Retired`. Starting two existing workers for the same market is not sufficient and can conflict over ownership.
2. `store.rs::event` automatically selects only slot 0 at initial startup. `select` exists but `main.rs` never calls it. A valid slot 1 cannot currently rescue startup automatically.
3. `tick` and `request_recovery` fail the processor when any replica exceeds its recovery budget. Without a deliberate degraded-mode policy, a failed standby would kill a healthy selected collector.
4. `worker.rs::run` publishes `Ended` after a close attempt of up to one second. Automatic failover must not unnecessarily wait for that close handshake after intake has already stopped.
5. `Replica.observed`/`last_received_at` do not implement rolling subscription-health windows. In the changes path they also advance before every change in the event has been successfully prepared. They cannot be reused unquestioningly as validated-health counters.
6. `market_data::envelope/decode` directly re-export the Polymarket parser; C4 calls these without dispatching on the adapter. C2 constructs Polymarket JSON and treats literal PONG specially. `manager.rs` imports `discovery::polymarket::Command`. These are concrete Extension 3 seams, not a reason to rewrite all components.
7. Lifecycle messages become `Event::NonBook`; workers do not enable `custom_feature_enabled`. C1 already has bounded `Command::Hint(MarketKey)` verification, but nothing routes WebSocket lifecycle hints into it.
8. Historical discovery reached 484,704 desired instruments with 44 unresolved records, not accepted coverage (`docs/protocol.md`). At two replicas this approaches 970 sockets with 1,000 assets/socket, before fragmentation/version separation. The 10-million-level budget permits only about 10 levels per replica on average at that historical scale, before replacement construction. Neither those defaults nor a 100-book benchmark establishes universe capacity.

## 2. Decisions and invariants

### Recommended baseline versus alternatives

| Choice | Decision and trade-off |
|---|---|
| One processing owner with two independent replicas | KEEP. No shared mutable books or extra data-plane handoff; parsing/memory cost rises with redundancy. Measure before sharding. |
| Select one source per book | KEEP. Failover emits a complete replacement snapshot; never race individual deltas from different sources. |
| First validated source at startup; sticky thereafter | ADD. Slot number does not justify waiting for a broken primary. Deterministic input order decides the initial winner. |
| Same-session unsubscribe/re-add as a health fix | DO NOT assume safe for Polymarket. Start with fresh-generation socket renewal; exact per-asset recovery needs a separately proven boundary. |
| Socket-local decode/books | BENCHMARK later against this baseline if the owner saturates. It complicates health comparisons, selection and ordered output. |
| One generic framework for discovery, authentication and all exchanges | REMOVE from initial scope. Separate registry commands from Gamma; use narrow wire capabilities, not a plugin platform. |
| Faster hasher, lock-free ring, dense ladders, busy spin | DEFER until a measured bottleneck and unchanged replay oracle justify them. |
| Kalshi production adapter | NOT authorized. Read its semantics to test our abstraction; no credentials, endpoints or trading implementation. |

### Ownership and pipeline

```text
C1 registry -- authoritative desired revisions --> C2 assignment manager
                                                   | same market, slots 0/1
                                          +--------+--------+
                                          |                 |
                                     socket A          socket B
                                          |                 |
                                          +--------+--------+
                                                   |
                                      existing ordered bounded ingress
                                                   |
                        C3 protocol normalization + C4 source replicas
                        health windows + selection on this same owner
                              |                         |
                    borrowed selected observations     | bounded repair intent
                              |                         v
                        C5 fixed pool             C2 manager/worker
                              |
                    binary stdout + integrity provenance
```

- Desired identity, source slot, assignment revision and connection generation are different dimensions. A reconnect changes generation, not logical slot. Readmission advances revision. Every delayed action validates all relevant dimensions.
- One selected binding per instrument. Every source has its own initialized book. Standby updates update only standby state; they are not duplicate output records.
- Preserve every selected update, including no-ops and repeated timestamps. A selection snapshot covers candidate state already processed; do not retrospectively output its earlier deltas.
- The snapshot must be accepted by C5 before any subsequent candidate delta can be emitted. Any sink failure is terminal; no rollback to the old source or repair snapshot.
- Retirement is a desired-state cutoff for **all replicas**, not failure of one source. It must fence late initial requests as well as already initialized replicas.
- Socket closure, silence suspicion, malformed financial data, resource exhaustion and output failure are distinct. Only expected source availability failures admit degraded operation. Accepted-ingress loss, malformed internal control, encoding and I/O errors remain terminal.
- Activity and deadlines use complete-message receive monotonic time plus owner clocks. Exchange time is not a sequencing or health clock. Queue age cannot be mistaken for exchange silence.
- Integrity/control records are never sent through lossy metrics. Low-rate diagnostic summaries may use latest-value replacement with an explicit superseded-summary count; exact source transitions and counters remain on their owning path.
- **Candidate contract:** `Live` means valid local reconstruction, not synchronized exchange position. Selection policy separately records initialization, receive-progress evidence, known lag/suspicion and unknown freshness. Neither recent traffic, equal quantities, exchange timestamps nor hashes prove cross-source equivalence. A lower quantity after switching does not by itself prove regression.
- **Scheduling contract:** every maintenance loop declares population, cadence, acceptable lateness and measured service capacity, including health, recovery, switching and minute snapshots. A bounded slice is insufficient if aggregate work stays perpetually overdue. Admission cannot claim support beyond the measured envelope.
- **Error contract:** distinguish replica degradation, instrument coverage loss and process integrity failure. The first two suppress only unusable sources/books and trigger bounded repair; malformed internal control, accepted-input loss and output failure remain terminal. Missing coverage prevents a complete-coverage claim even while healthy books continue recording.

This is evaluation cadence, not total silence detection time: window lag, two-observation confirmation and input queue delay must also be reported. Hard invalidations enqueue immediate dirty work; evaluate candidate eligibility again at selection, never rely only on the last sweep.
- [ ] Derive the minimum examination rate from population/cadence. At 484,704 instruments, a 10s pass requires at least 48,471 instrument checks/s (about 96,942 replica checks/s); the former 1,024 replicas/100ms proposal needs 94.7s and is rejected for this envelope without further benchmarking. Start with a resumable cursor over compact health state, sized to the required rate and serviced in bounded slices between messages, including when ingress is continuously ready. Measure achieved rate and lateness under mixed load. If this cannot meet the contract, use a bounded due-time index following the existing snapshot deadline pattern, with one scheduled entry per instrument and no heap insertion per delta. An index reduces unnecessary checks, not the service requirement for due work. Choose the simpler measured design; reject a full-universe claim if neither meets the budget.
- [ ] Replace repeated universe scans for initialization/recovery deadlines with a bounded outstanding-deadline index if the R0 workload shows them violating the same scheduling budget. Keep a scan reference in deterministic tests. For health, failover, recovery and snapshots publish maximum overdue age and pending work; a 1ms slice alone is not acceptance. Include idle ingress, constant ingress and synchronized deadline bursts in tests.
- [ ] Initial policy candidates, persisted in the run metadata: 60s warmup; compare only overlapping valid windows; suspect a source with zero changes while a peer has ≥5 in the last 60s, or ≤10% of peer changes when the peer has ≥20; require two evaluations separated by ≥10s. These are heuristic starting values, not exchange guarantees. Reset confirmation when evidence recovers.
- [ ] Only in single-source mode or with an unavailable peer, compare the current complete minute to a stable prior baseline: require prior three complete minutes each ≥20 changes and current <10% of their mean for two complete minutes. Freeze the baseline at the first low minute; clear it on recovery. Both initialized peers quiet is **quiet/unknown**, not grounds to repair both. This heuristic can mistake a real slowdown for failure; periodic renewal still probes long-quiet subscriptions without reconnect storms.
- [ ] Feed rate suspicion into R3's eligibility policy. Pause soft silence decisions when processed ingress age exceeds an initial 1s lag budget; report monitoring lag, keep known invalidity, and mark freshness unknown rather than calling a backlogged source current. Hard session ends and validation failures still act when processed. Do not require recent exchange timestamps: a legitimate fresh snapshot can describe old activity. Recent arrivals can also be delayed history; report evidence, not synchronization guarantees.
- [ ] On suspicion, suspend that source's publishing eligibility at an explicit owner cutoff, prefer a qualified peer and request fresh-generation renewal. Retain its independent book for diagnosis but require reinitialization before reuse. Log suspicion separately from confirmed malformed-data gaps; do not backdate certainty to the last update.
- [ ] Implement literal low-rate subscription repair conservatively: remove affected subscriptions on the old session where feasible, then close it and resubscribe its authoritative desired set on a new generation. Unsubscribe-write uncertainty also closes the session. Use the existing bounded send path. Do not claim this is isolated per-asset recovery; report all books affected by the full-session renewal. Same-session remove/re-add stays disabled until a replay boundary is proven.
- [ ] Budget renewal start-to-start interval, start rate and concurrency from R0's measured full reinitialization times, physical socket limits and peer coverage. Initial target is 30min plus deterministic 0–5min jitter, not a promised interval. At 970 sockets/30min, demand is 0.539 renewals/s; two concurrent slots require average occupancy below 3.71s with no margin. At 10–20s occupancy, the arithmetic minimum is 6–11 slots before safety margin. Do not blindly adopt those counts: include tails, unavailable books, conflict reservations and spontaneous recovery, and lengthen the declared interval if the safe connection budget cannot sustain the target.
- [ ] Count a renewal slot as occupied until all still-desired assigned books have fresh baselines, or the attempt explicitly expires into degraded recovery; handshake completion alone does not release it. A timed-out attempt may release a global concurrency permit but cannot authorize renewing a peer with missing coverage. Begin at a conservative probe concurrency of two and one new scheduled connection/s, then qualify the operating budget under load. No overlapping voluntary renewals per instrument; mandatory reconnects have reserved capacity in the shared limiter and cannot be starved. Record planned/actual intervals, time in queue, full-ready latency and overdue maintenance. If backlog grows in a steady-state trial, the schedule fails qualification.
- [ ] Before voluntary renewal, reserve its affected instrument set on the book owner and select healthy peers for every publishing book on that worker, with snapshot boundaries. Revalidate assignment/generation and peer availability before granting a bounded renewal intent. The manager executes the grant, not a duplicate health policy. Release reservations on reinitialization, cancellation, retirement or explicit timeout; timeout must not permit another renewal without checking current coverage. If no peer is ready, defer and report overdue maintenance; never voluntarily drop the sole good source just to satisfy a timer. An unexpected peer failure after a grant can still cause a gap and must be reported. In one-replica mode explicitly allow the documented gap or require redundant mode for guarded rotation.
- [ ] Use one bounded pending renewal per worker with session identity and reason; cooldown 60s after recovery. Prioritize actual failures over suspicion over scheduled renewal. Record requests, deferrals, completions and time-to-initialize. Stop scheduling at SIGINT; drain accepted state/output as before.
- [ ] Test active-vs-silent peers, both quiet, a market-wide slowdown, rejected-message spam, stale counters after reconnect, clock jumps, owner backlog, repeated alerts, channel saturation, simultaneous renewal deadlines, retirement and SIGINT. Include asymmetric slot packing where one worker overlaps several peer workers, reservation expiry and peer failure after a grant. Both replicas of any instrument must never be voluntarily renewed before one is usable again.

**Gate:** no false "healthy because PONG" decision; no storm under quiet fixtures; correct repair and rotation with asymmetric traffic. Benchmark 50k/100k/500k replicas and the observed full target (historically about 970k) with data flowing; report p99.9, revisit/detection lateness, pending work and per-replica bytes. Accelerate clocks for multiple complete renewal cycles with measured latency distributions and failure bursts, then validate a bounded real-time run. No unbounded renewal backlog or healthy-peer coverage violation. Smaller passed tests do not qualify a larger universe.

- [ ] Build the matcher against deterministic fixtures first: delayed identical events, repeated identical quantities, same timestamps on distinct events, reordered independent assets, missing events, changed JSON whitespace/array batching and repeated hashes. A hash alone must never establish event identity.
- [ ] Match per-asset canonical financial event content (kind, exact ID, exchange timestamp, ordered levels/entries and available hash) within bounded candidate windows, preserving each source's order. Fingerprints may accelerate lookup, but verify full canonical content equality before accepting a match. Separate initialization/replacement snapshots from ordinary changes. Require unique compatible matches; otherwise count ambiguous/unmatched, do not force pairings by occurrence index. Without exchange IDs this remains heuristic matching.
- [ ] Preserve old candidate ambiguity after eviction: expire the entire affected matching window and mark it censored, rather than treating a formerly repeated key as newly unique. - [ ] Stamp wall and monotonic receive time at complete-message delivery; compute signed `B_receive − A_receive` on the same host. - [ ] Report end-to-end processing/output separately from network arrival differences. Measure source selection hysteresis and reconnection cost before turning any measured advantage into automatic latency-based source switching; R3 deliberately remains sticky.

## 4. Cross-stage acceptance matrix

| Failure / workload | Required observable result |
|---|---|
| Primary unavailable at startup | Valid standby can initialize selected output; no waiting forever for slot 0 |
| Primary disconnects during active updates | Ordered end, unavailable provenance, candidate snapshot, then candidate deltas |
| Standby recovery exceeds its budget | Explicit degraded redundancy while healthy selected stream continues |
| Both sources invalid/uninitialized | No deltas/snapshots for that book; overdue coverage plus bounded retry/cooldown, healthy books continue |
| Live candidate has unknown freshness | Explicit degraded selection provenance; no claim of synchronized or recovered history |
| Candidate known lagging or suspect | No selection until reinitialized/requalified by the declared policy |
| Reconciliation interrupted mid-chunk sequence | Accepted fences preserved; incomplete revision recorded, no complete-admission claim |
| One subscription silent but peer active | Count-based suspicion, guarded switch, bounded fresh-session resubscription |
| Both peers quiet | Quiet/unknown; no rapid false-failure loop; staggered renewal still operates |
| Global retirement while either source disconnected | All slots fenced; late requests/data cannot resurrect old revision |
| Planned rotation with no ready peer | Defer/report; do not intentionally remove sole coverage |
| Full ingress/output or partial write | Terminal, accepted-prefix accounting; no hidden standby bypass/drop |
| Decoder/relative update fails mid-event | No partial financial mutation; invalidate correct scope |
| Monitoring/rotation/research can't keep up | Explicit overdue/censored evidence and failed operating-envelope qualification |
| Process crash | Surviving independent process only if separately running; no same-process availability claim |

No p99 budget is invented for the whole live system. Before optimization acceptance, declare an operating envelope from measured offered traffic, depth, sockets, output speed and deployment host. Compare baseline/candidate over identical inputs with repeated trials; report all percentiles, samples, achieved throughput, scheduling lag, memory and losses. Correctness gates are zero mismatches and explicit failure; performance gates are measured capacity and tails within the declared envelope.

## 5. Verified references and what they do not prove

1. [Voluntas challenge](https://voluntas.io/engineering-challenge), fetched 2026-10-27: precise core and extension requirements. Polymarket is an allowed alternative; Kalshi implementation is not additionally mandatory.
2. [Polymarket market-channel AsyncAPI](https://docs.polymarket.com/api-reference/wss/market), fetched 2026-10-27: asset subscriptions, initial snapshots, absolute new aggregate size, PING every 10s, optional lifecycle notifications. It documents neither a replay guarantee nor a safe causal fence for same-session unsubscribe/re-add. Snapshot hash and change hash descriptions differ; neither is a documented unique stream sequence.
3. [Polymarket discovery](https://docs.polymarket.com/market-data/discover-markets), fetched 2026-10-27: explicit V1/V2 filtering, cursor pagination, V1 token IDs versus V2 position IDs. This does not make the listing an atomic universe snapshot. Preserve local fixture/documentation discrepancies recorded in `docs/protocol.md`.
4. [Polymarket rate limits](https://docs.polymarket.com/api-reference/rate-limits), fetched 2026-10-27: IP-based request throttling can delay/queue requests. HTTP limits are not a documented CLOB WebSocket subscription/connection budget. Do not infer socket ceilings from other APIs.
5. [Kalshi orderbook updates](https://docs.kalshi.com/websockets/orderbook-updates), fetched 2026-10-27: authentication, market tickers, signed quantity deltas, subscription-local `sid/seq`, `get_snapshot`, market-scoped cross-connection `clock` and maintenance resets. These documented Kalshi capabilities **must not be projected onto Polymarket**. Optional timestamps also prevent claiming a new venue needs only a JSON spelling change.
6. [Tokio 1.54.1 `select!`](https://docs.rs/tokio/1.54.1/tokio/macro.select.html), matches Cargo.lock: branch fairness and cancellation safety. A selected handler awaiting a subscription write does not keep polling its sibling receive branch. Keep uncertain-write session termination; change task topology only after measured receive-stall evidence.
7. [Databento feed-handler lessons](https://databento.com/blog/why-we-didnt-rewrite-our-feed-handler-in-rust): narrow scope, minimal shared state and simpler concurrency. The article explicitly did not benchmark Rust against C++; its throughput numbers are not targets or evidence for this collector.
8. [LMAX Disruptor guide](https://lmax-exchange.github.io/disruptor/user-guide/index.html): single-writer ownership, bounded publication, reuse and consumer gating. Borrow the principles, not a new ring buffer or busy-wait strategy. Its rewindable transactional examples do not authorize replaying partially written stdout buffers.

**Review outcome:** the user's gap table is substantially accurate. The next engineering work is source identity/retirement correctness and observed coverage, followed by real redundancy and monitoring—not another speculative bytes-level rewrite. Full live acceptance and controlled research remain separate evidence gates even after implementation.
