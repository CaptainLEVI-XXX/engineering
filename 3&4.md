Do not commit or push without authorization. Execution evidence and remaining sign-off gaps are recorded in `docs/protocol.md` and `docs/revision-check.md`; the task lists below remain the original acceptance specification, not automatic completion claims.

**Architecture:** Retain Component 2's bounded ingress and one synchronous processing owner. ## 1. Scope and completion claims

Priority: **correctness → data integrity → deterministic replay → predictable latency → sustainable throughput → simplicity**. This is an L2 market-data collector for backtesting, not an execution or matching engine.

The project target includes the mandatory collector and **all four extensions**. Work assigned to later stages is required future delivery, not optional functionality. This implementation covers only C3/C4 and necessary narrow C2 integration. AGENTS.md now records that approved scope.

| Requirement | C3/C4 deliverable | Required later delivery |
| --- | --- | --- |
| Base collector | Exact decoding, replacement snapshots, absolute updates, validity and ordered observations | C5: supplied-helper binary stdout, snapshots every minute, buffering, SIGINT drain/flush and reader round-trip |
| Extension 1: redundant WebSockets | Independent source replicas; deterministic selection API and snapshot-on-switch tests | Redundant subscription provisioning, health-based selection and live failover |
| Extension 2: subscription monitoring | Per-source/instrument activity and initialization state, bounded recovery hooks | Activity-window policies, unsubscribe/resubscribe and staggered periodic socket rotation |
| Extension 3: exchange-generic encoding/decoding | Exchange-neutral storage and orchestration contracts; Polymarket-specific interpretation | Verify the integrated subscription/codec boundary; Kalshi implementation only if separately requested |
| Extension 4: latency experiments | Preserve source identity and receive timestamps; measure decode/reconstruction | Controlled connection experiments and a Markdown account of results, including full receive-to-output measurements |

No automatic rebalancing, Kalshi transport, relative-delta implementation, redundant socket allocator, SBE writer, SIMD, custom allocator or custom lock-free structure belongs to this implementation slice.

Distinguish these claims throughout tests and reports:

- Transport-accepted messages: successfully admitted to C2 ingress.
- Validated/committed events: accepted by C3/C4's financial and source contracts.
- Selected output observations: changes chosen for the single recorded history of each instrument.
- Exchange-wide history: not proven complete by any of the above. Polymarket has no established gap-free replay guarantee in the evidence reviewed here.

A fresh snapshot restores present state, not missed history. Redundant sockets reduce exposure to source failures; sockets within one process do not protect against that process crashing or shared output failing.

## 2. Existing interfaces and necessary changes

Read these owners before implementation:

| Existing path | Contract to preserve |
| --- | --- |
| `src/discovery/mod.rs` | Adapter-scoped identities and authoritative desired state; Gamma market IDs are not WebSocket condition IDs |
| `src/websocket/manager.rs` | Assignment ownership; retirement followed by re-admission can select another worker |
| `src/websocket/worker.rs` | Single socket owner, session generations, requested state, complete-message receive timestamps |
| `src/websocket/ingress.rs` | Bounded ordered envelopes; retain the envelope until processing finishes to retain its byte permit |
| `src/main.rs` | Existing dedicated consumer thread, session/ordinal checks, accepted-prefix drain and incomplete-boundary reporting |
| `src/side.rs` | Reuse `Side::Buy` for bids and `Side::Sell` for asks; preserve SBE discriminants |
| `tests/websocket.rs`, `tests/collector.rs`, `tests/ingestion_load.rs` | Existing transport, executable and load behavior; retain transport-only coverage |

C2 currently emits `Started(Session)`, `SubscriptionsRequested { session, add, remove }`, `Data { session, ordinal, received_at, payload }`, and `Ended { session, reason }`. A session identifies worker, generation and adapter. A successful subscription write is not exchange acknowledgement or book initialization.

Two narrow C2 changes are necessary when implementing this plan:

1. Carry assignment identity/revision through commands and successful-request notifications, so cross-worker re-admission cannot confuse ownership. This is control-plane metadata, not JSON parsing inside workers.
2. Accept bounded, session-checked recovery requests from the processor. C2 continues to own socket restart and reconnect scheduling; C4 owns the decision that a replica lacks a trusted baseline.

**Implementation refinement:** the manager additionally publishes an ordered
`Retired { worker, adapter, revision, assets }` cutoff before dispatching removal.
Successful-request notifications cannot represent retirement when the socket is
disconnected or an unsubscribe write fails. The cutoff retires slot 0 without
claiming an exchange acknowledgement; later request notifications are idempotent.
An unrequested retirement can retain a bounded inactive tombstone with generation
zero (no connection), never a live replica. This prevents false recovery deadlines
and obsolete Add notifications resurrecting retired assignments.

Do not otherwise refactor C1 or replace C2's queue/runtime. Their existing tests must remain meaningful after these interface changes.

## 4. Identity, source replicas and output selection

### Separate roles

- **Instrument:** `(AdapterId, exact external asset ID)`, resolved to a stable internal `BookId(u32)` using checked allocation. `BookId` identifies an instrument, not a connection's book.
- **Logical source slot:** one intended subscription replica of that instrument. Slot 0 is sufficient for today's single-source manager; later redundant provisioning adds independent slots. A worker ID is not the logical slot because assignments may move.
- **Assignment revision:** monotonically advances for a slot's removal, re-admission or reassignment. Reconnecting an unchanged assignment uses the same revision and a new session generation.
- **Replica binding:** instrument + logical source slot + assignment revision + complete C2 session. Levels and validity belong to this binding.
- **Selection:** the exact replica binding currently supplying an instrument's output. Selection does not merge replicas or establish exchange-wide freshness.

Use a `Vec` of instrument slots and adapter-scoped `HashMap<String, BookId>` indexes with borrowed `&str` lookup. Each instrument owns its small collection of source replicas and selected binding. Start with straightforward bounded collections; do not create a generational arena or global redundant index without need.

Keep stable instrument IDs without reuse initially. Bound retained identities and release inactive replica levels when no borrowed observation still needs them. Never create an instrument merely because an unknown ID appears in data.

### Assignment and session rules

The manager owns slot assignments/revisions. Workers preserve this context across reconnect and carry it into successful-request notifications. The processor tracks the latest accepted revision per instrument/source slot, including retirement tombstones.

- Older-revision Add/Remove notifications cannot overwrite a newer binding.
- Data must match an active session and a currently requested binding; a worker-local generation cannot be compared with another worker's generation.
- Remove/Ended only affect the bindings they actually identify. A late old-session Ended cannot invalidate a new replica.
- Two explicitly assigned source slots may be live simultaneously. Two concurrently assigned workers for the same slot/revision are an integrity error, not implicit redundancy. An ordered reconnect of the same assignment replaces its old session binding normally.
- Control effects take place at their position in the accepted ingress trace. Do not retroactively discard earlier accepted source observations.
- Preserve same-worker remove/re-add session rotation. Initial requested bindings on reconnect must include current revisions, not reconstructed guesses from stale state.

Distinguish late data from a superseded assignment on a still-active socket from a violation of transport ordering. The former is ineligible for book mutation; data outside its active C2 session or with a broken ordinal remains a run-level integrity error under the existing transport validator.

For a testable transfer: slot 0 moves from A/revision 1 to B/revision 3 after removal at revision 2. B's Add/snapshot may be observed before A's removal. Revision 2 must not retire revision 3; subsequent A data is not eligible to mutate B. Slot 1 on C remains an independent valid replica throughout.

### Selection contract

The initial single-source path may select its assigned slot once initialized. Expose an explicit selection operation for deterministic tests and later policy code; do not build automatic health-based switching here.

Selecting a different replica requires a live, current binding and exposes a complete snapshot before any of that binding's subsequent selected deltas. This boundary is required even if the two books compare equal. A failed selection leaves the previous usable selection unchanged; if it is already invalid, output remains unavailable.

Non-selected replicas consume their own snapshots/deltas but do not duplicate selected output. A source switch does not replay all previously observed backup deltas or repair missing selected history. Never choose a replica solely because its exchange timestamp is largest.

## 5. Component 3: exact decoding

### Numeric and timestamp contract

Use small validated `Price(i64)` and `Quantity(i64)` types at scale `1_000_000`. Reuse existing `Side`; defer `SignedDelta` and Kalshi relative arithmetic.

| Decimal string | Scaled result or action |
| --- | --- |
| `0.65` | `650000` |
| `100.5` quantity | `100500000` |
| `0.000001` | `1` |
| `0.0000001` | Reject; no rounding |
| `1.0000000` | `1000000`; extra zero precision is exact |
| `9223372036854.775807` quantity | `i64::MAX` |
| `9223372036854.775808` quantity | Reject overflow |
| Negative quantity, exponent, empty string, whitespace inside number | Reject |

Use checked integer arithmetic only. Define the adapter grammar as unsigned digits with an optional decimal point followed by digits; reject signs, missing integer/fractional digits and exponent notation. Price range restrictions belong in Polymarket validation, not generic storage. Zero deletes incremental levels and is omitted from stored snapshot levels.

Keep C2's original receive timestamp. Convert documented exchange milliseconds to microseconds with checked arithmetic and schema-range checks. Missing mandatory Polymarket event time is an integrity error, never receive-time substitution or epoch zero. Generic event metadata must represent absent exchange time without pretending it is present; a future adapter must resolve output compatibility before enabling such records.

### Parsing and lifetime

Validate complete outer JSON syntax before applying any contained event. Then process independent top-level events in their original order. Typed Serde is the successful-path baseline; `RawValue` slicing is an option for event isolation, not a claim of parsing only once.

Do not require strict borrowed `&str` for every numeric field. Escaped JSON strings such as `"\u0030.5"` must decode to the same value as `"0.5"`. Prefer numeric deserializer visitors accepting both borrowed and temporary decoded strings, immediately producing exact values. Where string identity must survive decoding, use a borrowing-aware fallback such as correctly configured `Cow<str>`.

Borrow only while the ingress envelope lives. Use reusable, bounded owned numeric scratch; no self-referential structs, transmute, additional payload-to-String copy or per-event queue. Enforce element limits during construction, not only after allocating a large `Vec`.

C3 classifies snapshots, ordered absolute changes, tick-size metadata and recognized non-book events. It does not access mutable books. The processing owner resolves IDs and performs state-dependent preparation. Only recognized non-book events are safely ignored for reconstruction; uncertain event semantics trigger the scope policy below.

## 6. Component 4: preparation, atomicity and storage

Each source replica stores two `BTreeMap<Price, Quantity>` sides. `Side::Buy` indexes bids, `Side::Sell` asks. Provide snapshot replacement, absolute set/delete, best-price access and ordered iteration. Canonical snapshot traversal is bids descending and asks ascending; incoming snapshot order need not already be canonical.

`BTreeMap` is a correctness baseline, not a measured winner. A sorted `Vec` may be faster for shallow books but pays for insertion/deletion shifts. Dense arrays require a justified price grid and tick-change policy. Compare alternatives only with representative depths/churn and the same oracle.

### Two phases owned by the processor

1. **Prepare:** interpret exact values, resolve identities, classify applicability, validate source binding, determine mutations/observations and preflight resource limits.
2. **Commit:** apply the prepared applicable changes in wire order, update validity and expose their ordered observations. No parsing, unresolved lookup, recoverable arithmetic failure, channel send or SBE encoding inside the mutation loop.

Snapshot preparation constructs a replacement independently, rejects duplicate prices on the same side (including duplicates involving zero), omits zero levels, and swaps only after validation. Do not sum duplicates. Empty/one-sided snapshots are valid; an old/equal timestamp alone is not grounds for rejection. Do not reject apparent crossing without verified protocol evidence.

For absolute changes, repeated entries remain distinct: old quantity 10 followed by 20, 30 produces final state 30 and two observations, 20 then 30. Repeated-key resource accounting must use the prior changes within this event. Ordinary errors cannot occur after partial financial commitment; allocator/process abort is not crash durability.

### Failure-isolation contract

| Condition | Action |
| --- | --- |
| Malformed complete JSON | No mutation from that message; unknown-scope source failure |
| Bad event in otherwise valid array | Isolate it where possible; preserve ordering of independent valid events while the run remains operational |
| Invalid identified snapshot | Keep old levels for diagnosis, invalidate that source replica |
| Malformed multi-asset financial event | Reject the entire logical event; invalidate all reliably identified affected replicas on that source |
| Valid update for known inactive/uninitialized replica | Account for non-application; do not mutate it or automatically invalidate healthy peers |
| Unknown asset in a book event | Do not invent a slot; report it. If affected registered scope cannot be established, use unknown-scope recovery |
| Ambiguous identity or unknown book-relevant semantics | Invalidate potentially affected replicas on that source and request bounded recovery; fail if safety/progress cannot be established |
| Superseded source data/control | No financial mutation or new-binding invalidation; diagnose and preserve transport accounting |

Validate the whole financial event before committing applicable entries. Applicability is not financial validity: a correctly encoded update for a removed asset is different from an invalid quantity. Whole multi-asset rejection on malformed input is a conservative collector policy, not an exchange transaction guarantee. Per-book salvage of malformed events is deferred.

On decode failure, use a bounded cold-path identity scan of the syntactically valid event. Typed deserialization's first error may conceal later affected assets. Missing/conflicting/duplicate identity fields make the scope ambiguous. Do not equate Gamma market IDs with WebSocket condition IDs or invent a mapping absent from C1.

Rejected financial events leave **levels** unchanged; validity and diagnostics may change. Replica A failure never automatically invalidates replica B from an independent source.

## 7. Validity, recovery and monitoring hooks

Replica states: `AwaitingSnapshot`, `Live`, `Stale`, `Inactive`. Live means initialized with no locally detected integrity failure, not proven complete exchange history.

| Input | Transition/action |
| --- | --- |
| Accepted Add/current session | Bind replica; await snapshot; start initialization deadline |
| Valid snapshot on current requested binding | Replace; enter Live; expose snapshot if selected |
| Valid delta on Live binding | Commit; expose delta only if selected |
| Delta before initialization or while stale | Account without applying/publishing |
| Invalid book-relevant event | Invalidate identified source scope; request recovery |
| Remove on current binding | Inactive; release selection if it refers to that binding |
| Ended/current session | Invalidate that session's replicas only |
| New session | Require a fresh baseline; never carry Live through reconnect |

### Bounded recovery

Use a bounded processor-to-C2 control path for restart requests targeting the complete current session. Coalesce pending requests per session, retain a reason and check obsolescence at execution. A request for generation 7 must not restart generation 8. Close/rotate the session and let the existing worker reconnect with current assigned subscriptions.

This socket-wide restart is the baseline because per-asset remove/re-add ordering has not been established as a safe same-session recovery mechanism. It temporarily affects healthy replicas sharing that socket; other sources remain independent. Do not splice REST snapshots into ongoing deltas without an ordering guarantee.

Set explicit initialization timeout, recovery deadline and finite attempt budget in configuration. Choose initial values from bounded fixture/live initialization measurements at Milestone 1, record the rationale, and test with an injected clock. Repeated bad data must not reset deadlines or replenish attempts. A full/closed recovery channel or exhausted budget is a visible coverage failure, not a dropped request. Cancellation on shutdown stops recovery scheduling.

Keep operating unaffected sources while a recoverable source fault is handled. If no valid selected replica is available, publish no deltas for that instrument and report unavailable coverage. C3/C4 does not silently choose a backup; explicit selection exercises that boundary and later automatic policy drives it. Unresolved required coverage at the recovery deadline fails the run. Shared queue/output failures remain run-level integrity failures.

### Monitoring and replay time

Expose per-binding requested/initialized state, last book-relevant receive time and counters for observed/validated/applied changes. Recognized non-book traffic and socket PONGs do not establish book liveness. Counter/window arithmetic must be bounded; do not log or allocate diagnostics per successful level update.

Quiet-market detection, comparative activity thresholds, unsubscribe/resubscribe policy and staggered rotation are later Extension 2 work. Rotation must avoid taking all replicas offline together. Quietness is evidence to investigate, not proof of a missing feed.

Replay must include logical timer inputs, selection requests and control boundaries as well as data. C2 boundary messages currently lack wall-clock times: use labelled input cursors for uncertainty boundaries unless capture is extended to record actual local control-observation times. Never substitute consumer processing time and label it socket receive time. Monotonic clock values are for duration measurement, not portable replay timestamps.

## 8. Resource and output contracts

### Bounded memory

Budget instrument slots, replica slots, levels per side/replica, total retained levels, event entries, snapshot construction and retained scratch capacities. Account for all backup replicas and peak **old book + replacement + payload + preparation/observation scratch**, not just final state.

Preflight intermediate level-count peaks: adding Y before deleting X can temporarily exceed a full book's budget even if final cardinality is unchanged. Repeated updates to one key must not be counted as independent permanent levels. Bound container growth while parsing. Keep stable identity tombstones within the slot budget; release inactive level storage and never clone the entire universe to achieve atomicity.

Exhaustion is an explicit coverage/integrity failure, not truncation, coalescing or implicit backup eviction. Logical counters and ingress byte accounting are not exact RSS guarantees; measure backing capacities and allocator effects. No custom budget allocator is required.

### Ordered observations for C5

Expose instrument identity/adapter, exact source binding, receive time, exchange time/provenance, input cursor `(session, ordinal, event index, entry index where applicable)`, observation kind, side, price and resulting absolute quantity. Control-triggered selection has its own recorded control cursor rather than a fabricated incoming event index.

Expose per-replica committed observations to tests/accounting while publishing only selected observations to the future sink. Do not retain an unbounded in-memory history: production accounting uses bounded counters and consumes each event's scratch before reuse; test collectors retain only their bounded trace. No-op updates and zero deletions remain observations; repeated entries must not be reconstructed by rereading only the final book.

Consume a borrowed snapshot view synchronously before the next mutation, or explicitly budget an owned copy. Do not retain references after releasing the envelope or mutate the book behind an outstanding snapshot view. Output/publication failure after commit stops publication and marks the run incomplete; do not retry the already-committed input as a fresh event.

For source-switch snapshots, retain the selected replica's state provenance and the local selection observation separately. A synthesized snapshot's creation time is not a new exchange event. C5 must choose and test the supplied timestamp-field mapping without inventing exchange time; carry enough information now to do so honestly.

Respect supplied SBE constraints now: signed scaled prices/quantities, checked unsigned microsecond timestamps, and 16-bit snapshot group counts. Reject unencodable cardinality before claiming a record is publishable; never split a replacement snapshot into ordinary independent replacement records without a reader-compatible contract. Preserve full external identity with adapter namespace in an unambiguous symbol encoding; compact IDs are internal, not unpersisted output symbols.

C5 still owns encoding, stdout buffering, snapshot scheduling, short-write/broken-pipe handling, chunk framing, reader compatibility and SIGINT flush. The schema has no dedicated gap record; retain diagnostics/uncertainty separately. C3/C4 alone cannot claim completion of the challenge.
