# Component 5 — Low-Level Recording Implementation Plan

> **For agentic workers:** Use the `executing-plans` skill and execute the milestones in order, in this checkout, without subagents. Checkboxes are acceptance work, not claims that it is implemented. This document authorizes no execution by itself. Do not commit or push without a new user request.

**Goal:** Record every selected C4 observation and periodic complete live-book snapshots as supplied-reader-compatible binary stdout, with bounded memory, explicit integrity provenance, and honest failure accounting.

**Architecture:** The existing synchronous C4 owner determines order and encodes borrowed observations into owned batches. One dedicated output thread writes those batches through the adapted supplied `AlignedSbeWriter` and writes ordered integrity metadata to a separate file. C4 retains all book, validity and source-selection authority.

**Tech stack:** Safe Rust, existing generated SBE codecs / `SbeEncode`, Crossbeam channels, existing Tokio supervisor, `std::io`, `serde_json`, `chrono`. No new runtime, queue library, allocator, serialization format for stdout, or production dependency is initially required.

**Spec:** [Voluntas challenge](https://voluntas.io/engineering-challenge), `AGENTS.md`, the supplied schema and helpers, and the contracts below. This plan replaces the earlier high-level review. Source inspection and linked documentation were checked on 2026-10-27; recheck the checkout before execution.

## 1. Scope, evidence and constraints

### In scope

- Selected initial/replacement snapshots, selected absolute level updates, periodic selected-live snapshots, and explicit selection snapshots.
- Exact symbol and timestamp mapping, binary stdout, aligned framing, bounded batching, integrity sidecar, failure propagation, shutdown, deterministic replay and output benchmarks.
- Necessary C4 integration: selected-output invalidation context, snapshot origin, and owner-side periodic capture. Necessary executable integration: recording startup, supervision and drain.
- Preserve C1 discovery, C2 transport/recovery ordering and C3 decoding. Preserve the existing transport-only mode and its empty stdout.

### Out of scope

- Automatic source selection, redundant socket provisioning, new reconnect/health policies, Kalshi implementation, raw-feed archival, compression, archive rotation, cloud uploads and durable storage guarantees.
- Book representation changes, worker-local book sharding, custom lock-free queues, busy-spinning, CPU pinning, SIMD, packed Rust structs, `unsafe` byte casts or compiler tuning.
- The eventual target includes all four challenge extensions. C5 supplies their recording integration points, not their implementations.

## 2. Recording contracts

### 2.1 Ordering and acceptance boundaries

1. C2 ingress establishes the accepted input order. C4 preserves per-source order and produces an ordered sequence of selected observations.
2. C5 preserves callback order exactly. Never sort by timestamp, deduplicate equal updates, coalesce levels or replace a burst with its final state.
3. A periodic capture occurs only between complete `Processor::process` calls, never inside a multi-level event or midway through an input message.
4. A single snapshot is encoded completely while the processing owner holds a coherent immutable borrow. No live-book borrow crosses a thread boundary.
5. Assign each SBE record a checked, run-local ordinal starting at zero. It is internal/sidecar metadata, not a new SBE field. File order remains authoritative.
6. Separate these counters: records fully encoded, records handed to output, records confirmed through a successful physical flush, raw bytes accepted by the underlying writer, complete logical chunks, and reader-compatible bytes. The confirmed-record counter is a conservative lower bound after an I/O error, not an assertion that no additional complete records escaped.
7. A failed run contains only a prefix, possibly ending inside a physical record/chunk. It is not a complete accepted-ingress archive. No later data may bypass the failure.

### 2.2 Financial and identity mapping

Use the existing integer values directly: price/quantity scale is 1,000,000. `Buy` maps to bid / 0; `Sell` maps to ask / 1. A zero quantity is emitted, not suppressed. All selected no-op and intermediate updates remain records.

Use `polymarket:v1:<exact-native-id>` and `polymarket:v2:<exact-native-id>`. The prefix is fixed per `AdapterId`; everything following it is the exact ID, including leading zeros. Never format IDs numerically or use process-local `BookId`, market title, YES/NO, hash, or a truncated ID as the symbol. Future namespaces must be unique and specified when their adapters are implemented.

Format/cache the symbol once per `BookId` on first selected observation in a bounded `Vec<Option<String>>`, capped by C4's instrument budget. This is serialization metadata, not a second registry. Reject an unexpected adapter/identity change for an existing slot. Count retained string capacities in memory reporting. A persisted integer-ID mapping is unnecessary because the symbol is self-contained.

### 2.3 Timestamps and snapshot origins

| Record | SBE local-time field | Exchange field |
|---|---|---|
| Selected level | Original `Metadata.received_at` → `backtest_timestamp` | Original `exchange_us` |
| Exchange snapshot | Original receive time → `received_at` | Original snapshot exchange time |
| Explicit selection snapshot | Selection time → `received_at` | Selected replica's last applied exchange time |
| Periodic snapshot | Actual capture time → `received_at` | Selected replica's last applied exchange time |

- Check conversions; never invent an absent exchange timestamp, clamp overflow, or substitute zero/receive time. Current Polymarket decoding already checks its exchange timestamp against the supplied reader's range.
- Convert receive/capture time to the schema's UTC microseconds. Document discarded sub-microsecond precision; do not advertise nanosecond archive timestamps.
- Use `Instant`/elapsed `Duration` for scheduling and latency; wall-clock jumps must not move monotonic deadlines.
- The last applied exchange timestamp is not the maximum timestamp seen. Do not sort or repair regressing exchange time.
- A periodic snapshot captures processed state, not all exchange activity before its wall-clock time. An older-receive-time update can follow it from ingress backlog, even for the same book. Replay applies file order, never a timestamp sort.
- Record snapshot origin, binding and C4 input cutoff in the sidecar. With only the supplied SBE file, snapshot origins and availability intervals cannot be distinguished.

### 2.4 Snapshot cadence

The operational target is a complete selected-live snapshot at most 60 seconds after the previous authoritative snapshot capture. Initial exchange, replacement and selection snapshots satisfy the baseline requirement and reset that book's due time; deltas never reset it. Empty initialized books are eligible. Standby, stale, awaiting-snapshot and retired replicas are not.

Use a C4-owned `BTreeSet<(Duration, BookId)>` deadline index, with at most one entry per selected-live instrument and an `Option<Duration>` due time in its instrument slot. Derive `Ord`/`PartialOrd` for `BookId` using its existing numeric identity. This is a standard-library ordered deadline set, not a custom scheduler. It is justified by earliest-due scheduling without a complete retained-book scan on every timer wake. Update it on snapshots/selection/availability transitions, not on each delta.

At each owner-loop boundary:

```text
check terminal output failure
process at most one ingress envelope, if available
capture due books in (deadline, BookId) order:
    re-read selected binding and validity
    sample actual monotonic and wall time immediately before each capture
    emit one coherent borrowed snapshot through the normal fallible sink
    on success, schedule actual_capture + 60 seconds
    stop after 64 captures, 65,536 captured levels, or 1 ms elapsed
    limits are checked between books; one book is never partially captured
publish an aged/large output batch; perform existing recovery work
wait only until the earliest data, snapshot, publication or recovery deadline
```

The batch/time limits are initial scheduling candidates, not proven latency targets. Expose the next snapshot deadline to the owner loop. If captures remain overdue, continue fairly with ingress at the next loop boundary; do not sleep 100 ms or wait for the queue to empty. The 100 ms recovery timer remains separate.

Record due time, actual capture time, late count and maximum lateness. This is not a hard-real-time OS: do not claim a strict 60-second bound just because a timer exists. If actual time reaches `due + 60 seconds`, a complete additional interval has been missed: terminate recording as incomplete rather than generating backdated catch-up snapshots. Smaller lateness is reported and must be included in performance sign-off. Do not generate historical snapshots retroactively.

On shutdown, stop scheduling new periodic work; drain accepted observations. An unfinished due sweep is reported, not backfilled from post-drain state. Natural session endings make affected books unavailable through the existing ordered ingress.

## 3. SBE encoding and framing design

### 3.1 Borrowed encoders

Add `recording/encode.rs` with small borrowed `SnapshotRecord<'a>` and `LevelRecord<'a>` views implementing existing `SbeEncode`. A view holds timestamps, `&str` symbol and either `&Book` or level values. Use generated `SnapshotEncoder` / `PriceLevelUpdateEncoder` methods; do not edit generated output or duplicate manual field offsets.

Expose `Book::side_len` to the crate for checked group counts. The current 65,535-per-side bound matches the generated `u16` count API. Recheck this against regenerated codecs before execution.

For current schema v2, including the 8-byte header:

```text
update_bytes   = checked(45 + symbol.len())
snapshot_bytes = checked(36 + symbol.len() + 16 * (bid_count + ask_count))
max_record    <= logical_chunk_bytes - 8
```

Keep these formulas next to the encoders and prove them against generated domain encoding, independently specified fields and the supplied reader. A maximum-depth current book needs 2,097,156 + symbol bytes, slightly over 2 MiB. Do not set a 2 MiB output-record cap that rejects books C4 admits.

Validate lengths, counts, required timestamps and available batch space before encoding. Reserve an uncommitted range, encode once into it, require the exact promised length, then publish its descriptor. On failure, truncate the range and fail the recorder. Never expose a partially encoded record.

### 3.2 Adapt the supplied helper, do not replace the format

Generalize `AlignedSbeWriter<W: Write = File>` in its existing file. Preserve `AlignedSbeWriter<File>::create(path, chunk)` and `write_msg(&impl SbeEncode)` for existing callers. Production passes already encoded records to the same framing owner through a crate-visible method.

Proposed interface contract (method names are implementation targets):

```rust
impl<W: std::io::Write> AlignedSbeWriter<W> {
    pub fn new(destination: W, chunk: usize) -> anyhow::Result<Self>;
    pub fn write_msg<T: SbeEncode + ?Sized>(&mut self, msg: &T) -> anyhow::Result<()>;
    pub(crate) fn write_encoded(&mut self, record: &[u8]) -> anyhow::Result<()>;
    pub fn flush_bytes(&mut self) -> anyhow::Result<()>;
    pub fn finish_chunk(&mut self) -> anyhow::Result<()>;
    pub fn finish(&mut self) -> anyhow::Result<()>;
    pub fn flush(&mut self) -> anyhow::Result<()>; // compatibility: finish_chunk
    pub fn into_inner_unflushed(self) -> W; // extract/disarm destination without I/O
}
```

`write_encoded` accepts only complete records produced by the checked in-process encoder. Do not decode every record again in production. `write_msg` uses reusable bounded scratch to encode a complete record before the framing method; production bypasses that scratch. Physical buffering belongs to a bounded `BufWriter` destination, not another 64 MiB allocation inside the helper. `into_inner_unflushed` enables terminal teardown; callers must explicitly finish on the successful path.

Framing algorithm:

```text
reject calls after terminal error or finish
reject zero-length or oversized record
if record.len > chunk_bytes - 8 - logical_offset:
    write zero padding through chunk end; logical_offset = 0
write complete encoded record; advance logical_offset

finish_chunk:
    if logical_offset != 0: pad to chunk end; logical_offset = 0
    flush physical destination, even if logical_offset was zero
finish:
    finish_chunk; enter Finished state
```

Keep production chunk size exactly `64 << 20`; it is not encoded in the file. Reserve an eight-byte zero sentinel and never let a record cross a logical chunk. Write padding from a reusable small zero slice, not a new 64 MiB zero allocation. An empty stream stays empty. `finish()` is idempotent after success. No error-producing I/O in `Drop` and no implicit retry on drop.

`flush_bytes()` does not pad or reset the logical offset. The output loop invokes it after at most 5 ms of pending physical data, including while the output queue stays busy. A nonempty logical chunk is completed after at most 60 seconds from its first record, as well as on rotation/finish. This bounds low-volume completed-file visibility at the cost of up to approximately 64 MiB of padding per low-volume minute. Both intervals are initial policy values to measure, not sub-millisecond claims. Check them between records; one blocking write can exceed either interval.

### 3.3 Physical progress and errors

Use `BufWriter<ProgressWriter<W>>`, initially 256 KiB, where the small `ProgressWriter` implements `Write`, forwards calls and counts successful underlying bytes. It exists to distinguish buffering from destination progress. `write_all` correctly handles short writes/`Interrupted`; the counter beneath buffering records each successful prefix. Treat `Ok(0)` on nonempty input as `WriteZero`. After any terminal error, poison the framing owner and discard unpublished retry intent.

Never call `flush()`/`finish()` again after a terminal write failure. A successful prefix may already exist; replaying the buffer would duplicate bytes. Ensure error teardown does not let `BufWriter::drop` silently retry its remaining buffer: explicitly disarm/extract it with `into_parts`, discard unwritten bytes and return a failure report. Apply the same discipline to buffered sidecar output.

After successful physical flush, advance a conservative confirmed-record count and completed-chunk count. After failure report exact underlying byte progress and the previous confirmation boundary; do not invent an exact final record count from a failed `write_all`. Reader-compatible bytes are complete chunks, not all bytes accepted by the OS. `flush` never means `fsync`, downstream consumption or durable storage.

## 4. Bounded handoff and integrity metadata

### 4.1 Owned batches and reuse

Add `recording/output.rs`. The production boundary uses Crossbeam, not an extra Tokio task per record. Use a fixed pool of 16 reusable batches. Each has a 4 MiB byte capacity and capacity for 4,096 entry descriptors; account actual capacities and descriptor sizes at startup. This deliberately reserves roughly 64 MiB plus descriptors for output, replacing the old whole-chunk buffer rather than adding an unbounded second store. It is an initial memory/latency trade-off to benchmark, not an assertion that all 64 MiB is useful queued payload.

```rust
enum EntryKind { Sbe, Integrity }
struct Entry { end: usize, kind: EntryKind }
struct OutputBatch {
    bytes: Vec<u8>,             // packed SBE records and JSON lines; never mixed on stdout
    entries: Vec<Entry>,        // strictly increasing ends; previous end gives start
    first_record: u64,          // SBE ordinal before this batch
    created_at: std::time::Instant,
}
```

The producer encodes directly into the current batch. The writer routes each slice by descriptor: SBE to the supplied framing helper, integrity to the sidecar. The descriptor is internal only. No per-level owned symbol, queue envelope, semaphore permit or reference-counted payload is needed.

- Publish at 256 KiB used bytes, descriptor exhaustion, record-does-not-fit, or 5 ms batch age. **Measured revision:** when a multi-batch pool has no recycled batch available, retain its last producer-owned batch on an age-only trigger and retry publication in 5 ms. Continue appending exact records within the same bounds; size/descriptor exhaustion still forces publication and then fails closed if no batch is available. This avoids wasting the last batch on a tiny tail while the writer is padding/stalled. A one-batch pool must publish to make any progress. A single larger admitted record occupies its own batch; its 4 MiB storage was already reserved.
- One bounded ready channel transfers batches; one bounded recycle channel returns ownership after consumption. These are two directions of one pool, not another processing stage.
- Pool invariant: `free + producer_owned + ready + writer_owned = 16`. Never allocate a replacement buffer on exhaustion. The configured admitted maximum record and maximum integrity line must fit one batch before startup succeeds.
- A new batch is obtained lazily when another record is needed. If none is available, fail closed with the first unaccepted observation/input position. Do not block the processing owner indefinitely, overwrite a batch or silently drop a generated snapshot.
- Preserve an earlier complete, producer-owned batch/tail on logical failure and attempt to drain it within shutdown bounds; do not include the failing range. Earlier handed-off batches remain FIFO. Distinguish this best effort from guaranteed drain on an I/O failure.
- Count symbol cache, pool capacities, physical stdout/sidecar buffers and test instrumentation separately. C2 ingress/book memory remains additional.

A 256 KiB publication target can still exhaust batch count before all reserved byte capacity is filled. The first 120-second replay failed at 60.12s with tiny aged batches exhausting the pool around chunk completion; a deterministic paused-writer regression reproduced the age-only failure with just three small records and two batches. Retaining the last producer batch on age-only triggers uses existing bounded capacity without blocking, coalescing or increasing allocation. This weakens the age publication target while output is already behind; report that delay honestly. Compare alternative pool sizes/targets only with the same overload semantics.

### 4.2 Sidecar contract

Recording mode requires `--integrity-path PATH`. Open with `create_new`, before starting network intake; do not overwrite existing history. Transport-only mode does not require or create a sidecar. Use versioned JSON Lines, bounded entries, no additional binary record types. Files are not transactionally atomic with stdout.

Emit these entries through the same ordered batch stream:

| Entry | Required fields and interpretation |
|---|---|
| Run start | Format version, run label (new sidecar path, start time and process id), schema id/version, chunk size, symbol grammar, bounded recording configuration and timestamp/cadence semantics. The label is descriptive, not a globally unique or cryptographic archive identifier. |
| Snapshot provenance | SBE ordinal, symbol, `Binding`, snapshot origin, C4 input cutoff, available source cursor, capture/receive time and exchange time; periodic due time when applicable. |
| Output unavailable | Next SBE ordinal, symbol, previously selected `Binding`, observation input, typed cause, bounded reason preview and detection time. Marks observed uncertainty, not the exact start of exchange loss. |
| Run end | Success or incomplete, records encoded/handed off/confirmed, raw bytes, completed chunks, snapshot lateness, first failure position if present, and whether intake/drain/output finish all succeeded. |

A snapshot entry identifies the corresponding SBE record, whether recovery, selection or periodic. A replacement snapshot closes an observed unavailable interval but does not retroactively repair history. A retirement cause distinguishes normal removal from recoverable unavailability. Standby failures remain diagnostic counters and do not open selected-output gaps.

Do not keep a second selected-binding map in C5. Extend C4 invalidation observations to carry `output_binding: Option<Binding>` captured before changing selection/assignment, plus `InvalidationCause::{SourceEnded, InvalidData, AssignmentReplaced, Retired}`. `None` means no authoritative output is affected. The outer observation binding may describe a new removal revision; `output_binding` identifies the old selected source that actually became unavailable. Preserve existing per-replica observations for other consumers.

Reason previews are bounded (128 Unicode characters); identity, ordinal, binding, cause and timestamps must be exact. Bound the serialized integrity entry at 8 KiB, including checked escaping; reject unsupported configuration/oversize metadata rather than truncate identity. Do not include complete unbounded error chains or CLI/environment secrets in the sidecar.

Before accepting a snapshot, reserve space for its complete SBE record and provenance entry together (two descriptors). Encode the SBE record and bounded JSON line into an uncommitted batch range; commit both only after both succeed. The writer processes them in that order. Serialize JSON through a capacity-limited slice writer, not an unchecked `Vec` append. Other integrity entries likewise reserve their maximum size before serialization. This makes producer-side acceptance coherent without pretending that the two output destinations commit atomically.

No stdout schema header/run marker is added. The run-start entry must be written/flushed successfully before the first binary batch. Subsequent sidecar data can be buffered; its logical ordering is established by record ordinals, not cross-file visibility. On successful shutdown: finish/flush stdout, write the final successful run-end entry, then flush sidecar. Any sidecar failure makes the run incomplete and stops further binary publication. Attempt a failure footer only when the sidecar remains usable; absence of a successful footer is itself incomplete. Readers must associate the sidecar with the intended captured stdout file; this plan does not promise cryptographic pairing or crash-atomic two-file commit.

### 4.3 Recorder-facing methods

`Recorder` owns the producer batch, ready sender, recycle receiver, symbol cache, checked record ordinal, producer failure state and the one-shot final producer-outcome sender. Its constructor validates budgets and accepts these endpoints from the output setup; it does not spawn a second processing thread. Implement these methods in `recording/mod.rs`:

```rust
impl Recorder {
    pub fn observe(&mut self, observation: Observation<'_>) -> anyhow::Result<()>;
    pub fn next_publish_at(&self) -> Option<std::time::Instant>;
    pub fn publish_due(&mut self, now: std::time::Instant) -> anyhow::Result<()>;
    pub fn finish(self, input_result: anyhow::Result<()>) -> anyhow::Result<()>;
}
```

`observe` validates/caches identity, maps origin and timestamps, appends a complete record/metadata pair as applicable, and publishes at the size/descriptor threshold. It samples a fresh publication clock only when starting a new batch, and a detection wall clock only for an integrity event needing it; do not add two fresh clock reads to every level update. `next_publish_at` is absent for an empty batch. `publish_due` checks age without creating empty batches. `finish` attempts to hand off the earlier complete tail, sends bounded producer counters/failure position and explicit input outcome, and closes its ready sender. Its success means producer handoff succeeded, not that output was written. The separate output result establishes that.

All these methods reject continuation after a terminal producer error, except `finish`, which is permitted solely to drain the earlier prefix and communicate failure. Keep details of worker setup private to `recording/output.rs`; its terminal result goes to the supervisor, not through the data queue.

## 5. C4 integration interfaces

Only the following responsibility changes are needed in `orderbook`:

```rust
enum SnapshotOrigin {
    Exchange,
    Selection { at: chrono::DateTime<chrono::Utc> },
    Periodic { at: chrono::DateTime<chrono::Utc>, due: std::time::Duration },
}
// Change Snapshot(&Book) to Snapshot { book: &Book, origin: SnapshotOrigin }.
// Move selected_at into SnapshotOrigin::Selection; do not retain two sources of truth.
// Extend Invalidated with typed cause and output_binding described in section 4.
```

Add `snapshot_interval: Option<Duration>` to C4 configuration, default `None` for existing validation consumers. Recording sets it to exactly 60 seconds; it is not a public live-mode tuning knob. Deadline indexing exists only when enabled. Keep source-specific replicas independent.

```rust
impl Processor {
    pub fn next_snapshot_due(&self) -> Option<std::time::Duration>;
    pub fn capture_due(
        &mut self,
        clock: &mut impl FnMut() -> (std::time::Duration, chrono::DateTime<chrono::Utc>),
        sink: &mut impl FnMut(Observation<'_>) -> anyhow::Result<()>,
    ) -> anyhow::Result<()>;
}
```

`capture_due` uses the fixed book/level/time limits in section 2.4 and actual clock samples between books. C4 counts levels, not SBE bytes; it must not import recording or know the wire layout. Increment the C4 input cutoff for each periodic capture, retaining the last source `Metadata` as provenance. Do not increment exchange-message counters or fabricate a source ordinal. Reject nonmonotonic test clocks. Any sink failure or missed-whole-interval error poisons the processor exactly like `process`/`select` errors.

Schedule/unschedule in the existing snapshot, selection, invalidation, retirement and assignment paths. Never reset a due time on an ignored standby snapshot, a delta or a duplicate no-op selection. If explicit `select` currently lacks a fresh monotonic sample, extend its arguments with `now: Duration` and update its callers; deriving a due time from stale `self.now` is not acceptable. Use owner clock time at exchange-snapshot application for its cadence baseline, while retaining original receive time in SBE.

The deadline set and instrument due field must agree after every transition. Tests should verify observable captures and failure behavior; an exhaustive scratch invariant check can inspect the index during development without becoming a permanent private-layout test.

## 6. Supervision, failure and shutdown

The output worker is a long-lived `std::thread`, not `spawn_blocking` per write. The existing supplied reader already targets Unix; for the current macOS/Linux targets, safely clone stdout's file descriptor once and give the worker the owned `File`. This avoids an additional standard-stdout line buffer and makes `ProgressWriter<File>` count OS-accepted bytes rather than bytes accepted by another userspace buffer:

```rust
use std::os::fd::AsFd;
let stdout = std::io::stdout();
let output_file = std::fs::File::from(stdout.as_fd().try_clone_to_owned()?);
```

Only the output worker writes to this descriptor; prohibit every other stdout write. The worker owns/closes the clone, not the process's original descriptor. No raw-fd ownership reconstruction, `unsafe`, global stdout lock or descriptor flag changes are needed. Retain one explicit 256 KiB physical buffer around it. Use injected `Write` implementations in tests. This is not a new Windows-support commitment or a nonblocking I/O backend.

The worker sends a terminal result through a oneshot to the existing Tokio supervisor. The supervisor must select on it even when no market data arrives. On failure it sets the existing stop signal immediately. The processing loop checks output failure/disconnection between envelopes and periodic captures. Avoid per-record status atomics; report progress at batch/flush boundaries.

Normal SIGINT/deadline sequence:

1. Stop discovery/reconnect scheduling and establish existing C2 intake cutoff.
2. Close workers and preserve ordered accepted ingress through session-ending events.
3. Stop periodic scheduling; drain accepted ingress through C4 and C5 while the sink is healthy.
4. Publish the last complete producer batch, close the ready sender and communicate producer success/failure via an explicit final outcome channel, not ambiguous channel closure.
5. Writer drains handed-off batches, finishes the last logical chunk and flushes stdout. It then completes the sidecar with the correct outcome.
6. Join finished threads and report counts. Success requires all stages, not merely `Processor::finish()`.

Failure matrix:

| Failure | Action |
|---|---|
| Encoding / sidecar preparation / no free batch | Stop processing permanently, stop intake, try to drain only the earlier valid prefix; incomplete exit. |
| Broken pipe / `WriteZero` / sidecar I/O error | Poison writer, notify supervisor, never retry retained buffer; incomplete exit. |
| Output worker panic | Supervisor treats lost terminal result as failure; no success footer. |
| Temporary downstream pause within capacity/deadline | Resume FIFO drain without changing data or timestamps. |
| Permanently blocked stdout or sidecar | Shutdown deadline expires: do not block on an unconditional join or claim flush/drain. Exit unsuccessfully; OS process termination ends remaining threads. |
| Missing producer outcome / missing orderly C2 end | Prefix only, no successful footer. |

For the initial Unix implementation, **choose best-effort graceful shutdown plus unsuccessful process exit on deadline**, not a new nonblocking OS-output subsystem. A timeout cannot cancel a started blocking write. At deadline, the executable must take an error-exit path that does not reacquire a stdout lock or wait on the blocked thread. On that path also avoid synchronous stderr writes that could block forever; the incomplete sidecar/footer state and nonzero exit are authoritative. Move existing supervisor shutdown-summary `eprintln!` calls out of the timed waiting sequence so they cannot prevent its deadline from being checked. Document that supervisors capturing stdout/stderr must retain exit status. Any hard process-exit path must be isolated to the binary, never a library API, and proven in a subprocess with both stdout and stderr unread. This does not claim that all existing unrelated logging has become nonblocking.

Reuse the existing shutdown timeout as the overall deadline; do not multiply it by sequentially giving each stage a fresh allowance. Finite buffers cannot guarantee capture through an infinitely stalled destination. Do not use the word durable for this shutdown.

## 10. Decision matrix and primary references

| Decision | Action | Reason |
|---|---|---|
| One C4 owner and one ordered output writer | KEEP | Coherent capture and deterministic record ordering; isolates blocking I/O. |
| Supplied codecs/schema/reader | KEEP | Required challenge compatibility. |
| Owned domain objects for every production record | CHANGE | Borrowed generated encoding avoids redundant symbol/level materialization. |
| 64 MiB logical chunk equals one physical write/buffer | CHANGE | Physical flush and logical framing have different latency contracts. |
| Periodic whole-universe stop-the-world sweep | CHANGE | Earliest-due bounded capture with measured lateness and no duplicate book store. |
| All replica invalidations imply archive gaps | CHANGE | Only authoritative output loss changes selected-book availability. |
| Existing four diagnostic samples as integrity history | REMOVE | Samples cannot describe all unavailable intervals. |
| Whole-buffer retry after partial I/O error | REMOVE | Can duplicate a prefix and corrupt framing. |
| Dedicated writer, pool/batch sizes and flush periods | BENCHMARK | Initial bounded design, not measured optimum. |
| Deadline cancels a blocking stdout write | REMOVE | Deadline bounds waiting, not OS write completion. |
| Nonblocking platform-specific output backend | DEFER | Initial contract uses honest unsuccessful exit on permanent stalls. |
| Additional workers, custom rings, SIMD, unsafe, pinning | DEFER | No measured bottleneck justifies them. |
| Automatic redundancy/health policy/Kalshi | DEFER | C5 provides integration; their components own implementation. |

References and the narrow claims they support:

1. [Voluntas engineering challenge](https://voluntas.io/engineering-challenge): stdout deltas, minute snapshots, supplied helpers, SIGINT, multiple sockets and all four extension definitions. Polymarket is an explicitly allowed alternative.
2. [Official schema](https://github.com/voluntas-io/engineering-challenge-template/blob/main/sbe_schemas/engineering_challenge/challenge_orderbook.yaml), local `sbe_schemas/includes/common-types.xml`, generated `OUT_DIR/challenge_orderbook.rs`: exact wire fields/counts, units and codec APIs. Generated-code inspection is necessary; protocol names alone do not establish byte layout.
3. [Rust `Write`](https://doc.rust-lang.org/std/io/trait.Write.html): partial writes, `Interrupted`, `write_all` failure and flush semantics. A returned error does not roll back earlier successful calls.
4. [Rust `BufWriter`](https://doc.rust-lang.org/std/io/struct.BufWriter.html): buffered visibility, drop error handling and `into_parts` for avoiding unintended retries during terminal teardown.
5. [Tokio stdout](https://docs.rs/tokio/1.54.1/tokio/io/fn.stdout.html) and [blocking tasks](https://docs.rs/tokio/1.54.1/tokio/task/fn.spawn_blocking.html): avoid uncoordinated writers; started blocking tasks are not cancelled by abort/timeout. Current processing is already on a dedicated thread, so do not misdiagnose it as async executor blocking.
6. [Databento feed-handler engineering](https://databento.com/blog/why-we-didnt-rewrite-our-feed-handler-in-rust): narrow responsibilities, minimal shared state and concurrency complexity. Their article explicitly does not provide a Rust-versus-C++ implementation benchmark; it proves no latency result for this collector.
7. [LMAX Disruptor user guide](https://lmax-exchange.github.io/disruptor/user-guide/index.html): single-writer ownership, bounded publication, reuse and consumer progress. These principles do not require importing its ring buffer or busy-wait strategy.
8. [Rust `Stdout`](https://doc.rust-lang.org/std/io/struct.Stdout.html) and [`BorrowedFd`](https://doc.rust-lang.org/std/os/fd/struct.BorrowedFd.html): safe `AsFd` access and cloning into an owned descriptor on the repository's Unix targets, without sharing standard stdout buffering.
